# Архитектура приложения

## Структура

```text
src/
  app/                 Expo Router: экраны и навигация
    (auth)/            Вход и регистрация
    (tabs)/            Основные вкладки приложения
    exercise/[id].tsx  Карточка упражнения по идентификатору
  components/          Переиспользуемые компоненты интерфейса
    ui/                Базовые элементы интерфейса
    workout/           Компоненты тренировок
    charts/            Графики прогресса
    exercise/          Компоненты карточки упражнения
  features/            Логика, состояние и сценарии по предметным областям
  lib/                 Клиенты внешних сервисов и общие утилиты
  hooks/               Общие React hooks
  constants/           Общие константы и настройки оформления
  types/               Общие TypeScript-типы
supabase/
  migrations/          Версионируемые изменения схемы базы данных
  functions/           Edge Functions
  seed.sql             Начальные/демонстрационные данные
assets/                Изображения, иконки и шрифты
docs/                  Продуктовая и техническая документация
```

## Границы модулей

- `src/app` содержит только маршруты и сборку экранов. Файлы здесь становятся URL-маршрутами Expo Router; повторно используемый код хранится вне этой папки.
- `src/features/<domain>` содержит сценарии домена: модели, запросы, локальное состояние и бизнес-правила. UI-части, которые нужны нескольким сценариям, выносятся в `src/components`.
- `src/components` содержит презентационные компоненты. Компоненты не должны напрямую владеть логикой доступа к данным.
- `src/lib` содержит интеграции и общие функции без привязки к конкретному экрану.
- `src/types` хранит общие типы. Типы, используемые только внутри одной feature, остаются рядом с ней.
- `supabase/migrations` — единственный источник истории изменений схемы БД; ручные изменения окружений должны быть отражены миграциями.

## Правила реализации

- Размещать Router-маршруты в `src/app`, как уже настроено в проекте; не создавать параллельный корневой `app/`.
- Сначала сохранять состояние на устройстве там, где сценарий должен работать без сети; синхронизацию с сервером изолировать в data-слое feature.
- Для списков и экранов тренировок учитывать узкий экран, безопасные зоны, клавиатуру и быстрые повторные рендеры.
- Не хранить секреты Supabase или сервисные ключи в клиентском приложении. Клиентский ключ и URL задаются через переменные окружения, доступные приложению.
- Не добавлять зависимости до появления конкретной потребности; Expo-пакеты устанавливать через `npx expo install`.

## Текущее состояние

Это каркас структуры. Папки доменных областей пока не содержат бизнес-реализаций; подключение Supabase, модели и экраны добавляются отдельными задачами.
