# Данные и база данных

Supabase является предполагаемым backend-хранилищем приложения. Начальная схема и политики Row Level Security описаны в `supabase/migrations/202611120001_initial_schema.sql`; миграция пока не применена к удалённому проекту, клиент приложения ещё работает на локальном хранилище.

## Предполагаемые сущности

- `profiles`, `profile_equipment`, `user_goals` — профиль, доступное оборудование и цели.
- `exercises`, `muscle_groups`, `equipment`, `exercise_muscle_groups`, `exercise_alternatives` — публичный каталог упражнений.
- `programs`, `program_days`, `program_exercises` — пользовательские и публичные программы.
- `workouts`, `workout_exercises`, `sets` — фактически выполненные тренировки и подходы.
- `body_measurements`, `personal_records` — замеры тела и личные рекорды.

## Соглашения

- Каждая миграция находится в `supabase/migrations` и имеет упорядоченное имя с временной меткой.
- Пользовательские записи связываются с `auth.users`; включаются Row Level Security и явные политики доступа.
- В приложении используются только публичные клиентские реквизиты. `service_role` и другие секреты допустимы только на серверной стороне.
- SQL начальных данных размещается в `supabase/seed.sql`; реальные пользовательские данные в seed не добавляются.

Перед подключением SDK нужно задать публичный URL/ключ проекта в окружении, применить миграцию и сверить схему с контрактами клиента. Секрет service role никогда не добавляется в мобильное приложение.
