# Данные и база данных

Supabase является предполагаемым backend-хранилищем приложения. До подключения SDK этот документ задаёт границы и соглашения, а не готовую схему.

## Предполагаемые сущности

- `profiles` — профиль пользователя и настройки.
- `exercises` — каталог упражнений.
- `programs`, `program_days`, `program_exercises` — программы и их состав.
- `workout_sessions`, `workout_exercises`, `sets` — фактически выполненные тренировки.
- `recovery_logs` — пользовательские записи восстановления.

## Соглашения

- Каждая миграция находится в `supabase/migrations` и имеет упорядоченное имя с временной меткой.
- Пользовательские записи связываются с `auth.users`; включаются Row Level Security и явные политики доступа.
- В приложении используются только публичные клиентские реквизиты. `service_role` и другие секреты допустимы только на серверной стороне.
- SQL начальных данных размещается в `supabase/seed.sql`; реальные пользовательские данные в seed не добавляются.

Перед созданием миграций сущности и ограничения необходимо сверить с продуктовыми сценариями.
